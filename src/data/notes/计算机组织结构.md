## 数据表示

### 机器数与四种码

以 n 位（含 1 位符号位）为例：

| 编码 | 正数 | 负数 | 0 的表示 | 表示范围 |
|---|---|---|---|---|
| 原码 | 符号位 0 + 绝对值 | 符号位 1 + 绝对值 | 两种（+0 / −0）| ±(2^(n−1) − 1) |
| 反码 | 同原码 | 符号位不变，其余按位取反 | 两种 | ±(2^(n−1) − 1) |
| 补码 | 同原码 | 反码 + 1 | **唯一** | −2^(n−1) ~ 2^(n−1) − 1 |
| 移码 | 补码符号位取反 | 同左 | 唯一 | 常用来表示浮点数的阶码 |

**补码存在的意义**：把减法变成加法。`a − b` 直接算 `a + [−b]补`，符号位一起参与运算、最高位进位丢弃即可，CPU 只需要一个加法器，不用单独做减法电路。

**为什么补码的负数多一个**：因为 0 只占一种编码，省下来的那个给了最小值。8 位补码的范围是 **−128 ~ 127**，不是对称的 ±127。

**求 −5 的 8 位补码**：`5 = 0000 0101` → 取反 `1111 1010` → 加一 `1111 1011`。

### IEEE 754 浮点数

| 精度 | 总位数 | 符号 S | 阶码 E | 尾数 M | 偏置 |
|---|---|---|---|---|---|
| 单精度 | 32 | 1 | 8 | 23 | 127 |
| 双精度 | 64 | 1 | 11 | 52 | 1023 |

- 阶码用**移码**表示，便于直接比较大小；真值 = (−1)^S × 1.M × 2^(E − 偏置)。
- 规格化数的尾数**隐含最高位的 1**，所以单精度实际精度是 24 位而不是 23 位。
- 阶码全 0：非规格化数或零；阶码全 1：尾数为 0 时是 ±∞，否则是 NaN。

**例：0.5 的单精度表示**

```
0.5 = 1.0 × 2⁻¹
阶码 E = −1 + 127 = 126 = 0111 1110
→ 0 01111110 00000000000000000000000  = 0x3F000000
```

> 注意：绝大多数小数（0.1、0.2……）无法用二进制精确表示，所以**浮点数不要用 `==` 比较**，要比较差值的绝对值是否小于某个精度。

## 存储系统

### 层次结构与局部性

```
寄存器 → Cache → 主存 → 辅存
速度 ↓        容量 ↑        价格 ↓
```

这一套能成立，靠的是**局部性原理**：时间局部性（刚访问过的还会再访问，所以循环体跑得快）、空间局部性（相邻地址会被一起用到，所以按"块"搬运划算）。

### Cache 的三种映射

| 映射方式 | 主存块能放哪 | 地址划分 | 优点 | 缺点 |
|---|---|---|---|---|
| 直接映射 | 唯一确定的行 | 标记 \| 行号 \| 块内地址 | 硬件最简单、最快 | 冲突率高 |
| 全相联 | 任意一行 | 标记 \| 块内地址 | 冲突最少、命中率高 | 比较电路多，成本高 |
| 组相联 | 组间直接映射，组内全相联 | 标记 \| 组号 \| 块内地址 | 两者折中 | —— |

- **替换算法**：直接映射不用选；组相联和全相联常用 LRU（最近最少使用），也有 FIFO、随机法。
- **写策略**：写直达（同时写 Cache 和主存，简单但慢）/ 写回（只写 Cache，换出时才写主存，快但要维护脏位）。

> 易错：地址划分里"组号"的位数是 log₂(组数)，不是 log₂(行数)。组相联里每组有若干行，行数 = 组数 × 每组行数。

### 命中率与平均访问时间

设命中率为 H，Cache 访问时间 Tc，主存访问时间 Tm：

```
Ta = H × Tc + (1 − H) × Tm          （未命中时按访问主存计算）
```

代入 H = 0.95、Tc = 1ns、Tm = 100ns：

```
Ta = 0.95 × 1 + 0.05 × 100 = 5.95ns
```

**只要 5% 的缺失，平均时间就被拉长了近 6 倍**——这就是命中率必须做高的原因。

> 另一种常见写法是把 Tm 定义成"缺失代价"（从主存补一块的额外开销），此时 `Ta = Tc + (1 − H) × Tm`。两个式子都对，**答题时写清 Tm 指的是哪一个**。

## 指令系统

### 指令格式

一条指令 = **操作码** + **地址码**。

- 操作码定长：译码简单，但指令字浪费。
- 操作码变长 / 扩展操作码：短地址码换更多操作码，代价是译码复杂。
- 按地址码个数分：三地址、二地址、一地址、零地址（如栈式指令）。

### 常见寻址方式

| 方式 | 有效地址 EA | 特点 |
|---|---|---|
| 立即寻址 | 操作数就在指令里 | 最快，但只能用于常数 |
| 直接寻址 | EA = A | 简单，寻址范围受地址码位数限制 |
| 间接寻址 | EA = (A) | 可扩大寻址范围，需要两次访存 |
| 寄存器寻址 | 操作数在寄存器中 | 快，完全不访存 |
| 寄存器间接 | EA = (R) | 一次访存 |
| 相对寻址 | EA = PC + A | 转移指令常用，便于位置无关代码 |
| 基址寻址 | EA = 基址寄存器 + A | 用于多道程序的重定位 |
| 变址寻址 | EA = 变址寄存器 + A | 适合数组遍历、循环 |

**RISC 与 CISC**：RISC 指令少而规整、定长、寻址方式少、多寄存器、适合流水线；CISC 指令多而复杂、变长、微程序实现。现代 CPU 多是"外 CISC 内 RISC"。

## CPU 与控制器：周期层次与两种控制器

---

### 易错点 1：周期大小关系颠倒

**正确顺序：**

```
指令周期 > 机器周期 > 时钟周期
```

- **指令周期**：执行一条完整指令
- **机器周期**：完成一个基本操作（如取指、访存）
- **时钟周期**：CPU 最小时间单位

> ❌ 常见错误：把"时钟周期"和"机器周期"的包含关系写反。

---

### 易错点 2：硬布线 vs 微程序控制器特性混淆

| 特性 | 硬布线控制器 | 微程序控制器 |
|:---|:---|:---|
| 速度 | ✅ **快** | 慢 |
| 修改/扩展 | ❌ **困难** | ✅ **容易** |

> ❌ 常见错误：以为"速度快"和"易修改"是同一个控制器的优点。

---

### 易错点 3：微操作层次不清

**正确层次：**

```
机器指令 → 微程序 → 微指令 → 微命令 → 微操作
```

- **微操作**：最小、不可再分的执行单位
- **微命令**：控制微操作的信号
- **微指令**：一组微命令的集合（可并行发出多个）
- **微程序**：完成一条机器指令的微指令序列

> ❌ 常见错误：混淆微指令和微命令的关系，或不清楚微操作是最小单位。

---

### 易错点 4：微程序控制器的映射关系

- 一条 **机器指令** → 一段 **微程序**
- 一段 **微程序** → 若干条 **微指令**
- 一条 **微指令** → 若干个 **微命令**
- 一个 **微命令** → 一个 **微操作**

> ❌ 常见错误：把"机器指令对应微指令"直接等同，忽略了中间还有微程序这一层。

---

## 指令流水线

把一条指令的执行拆成若干段，让不同指令的不同段重叠起来。经典五段：

```
取指 IF → 译码 ID → 执行 EX → 访存 MEM → 写回 WB
```

理想情况下，流水线满负荷后**每个时钟周期完成一条指令**，加速比接近流水段数 k。实际受三件事拖累：

| 冒险类型 | 起因 | 常见解决办法 |
|---|---|---|
| **结构冒险**（资源冲突）| 多条指令同时争用同一部件（如同时取指和取数据）| 指令 / 数据 Cache 分离、重复设置部件 |
| **数据冒险** | 后一条指令要用前一条还没写回的结果（RAW 最常见）| 转发 / 旁路、插入气泡（停顿）、编译器调度 |
| **控制冒险** | 分支指令改变了 PC，后面取来的指令白取 | 分支预测、延迟槽、提前预取分支目标 |

> 记法：**结构是"抢部件"，数据是"等结果"，控制是"猜错路"**。

再往上还有超标量（一个周期发射多条）、超流水（分段更细）等，本质都是想让并行度更高。

## 总线与 I/O

### 三类总线

| 总线 | 方向 | 宽度决定什么 |
|---|---|---|
| 数据总线 | 双向 | 一次能并行传多少位（决定数据通路宽度）|
| 地址总线 | 单向（CPU → 外）| 能寻址多大空间（n 位 → 2ⁿ 个单元）|
| 控制总线 | 双向 | 传送读写、中断、时钟等控制信号 |

同步总线靠统一时钟，时序简单但对慢速设备不友好；异步总线用握手信号，能适配不同速度的设备。

### 三种 I/O 控制方式

| 方式 | CPU 参与程度 | 适合场景 |
|---|---|---|
| 程序查询（轮询）| 全程忙等，一直被占用 | 设备少、结构简单 |
| 中断 | 传送期间不参与，每次传完打断一次 | 中低速设备、随机请求 |
| DMA | 只在开始时初始化、结束时收尾——整块数据由 DMA 控制器搬 | 高速、大批量（磁盘、网卡）|

**中断处理的大致过程**：关中断 → 保存断点 → 识别中断源 → 转中断服务程序 → 恢复断点。

**DMA 和中断的关键区别**：DMA 不逐字占用 CPU，且通常在总线上的优先级更高；两者并不互斥——常见做法是 DMA 传完一整块后用中断通知 CPU。

## 记忆口诀

| 口诀 | 含义 |
|:---|:---|
| **指机时，大到小** | 指令周期 > 机器周期 > 时钟周期 |
| **硬快难改，微慢易扩** | 硬布线快但难改，微程序慢但易扩展 |
| **程指令，令命令，令操作** | 微程序→微指令→微命令→微操作 |
| **补码减法当加法** | a − b 算 a + [−b]补，最高位进位丢弃 |
| **阶码移码好比较** | IEEE 754 的阶码用移码，偏置 127 / 1023 |
| **直唯全任组折中** | 直接映射位置唯一、全相联任意放、组相联两者折中 |
| **结构抢、数据等、控制猜** | 三类流水线冒险的起因 |
| **DMA 搬整块，中断搬一次** | DMA 只在首尾要 CPU，中断每次都要 |
